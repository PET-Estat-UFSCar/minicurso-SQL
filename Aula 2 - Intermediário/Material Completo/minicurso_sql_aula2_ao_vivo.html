Que tipo de valor vai em cada coluna?

Tipo usado na aulaExemplosColunas do banco
INTEGER1, 250, 4 → números inteirosIDs e quantidade
TEXT"Ana", "São Carlos", "2026-01-15"nome, cidade, categoria, data_pedido
REAL369.70 → número com parte decimalpreco

A data é guardada como TEXT no formato AAAA-MM-DD. O SQLite não tem um tipo exclusivo para datas.

SQLite usa afinidade de tipos: em tabelas comuns, o tipo declarado orienta conversões; não é uma validação rígida de todo valor. REAL usa ponto flutuante e pode ter aproximações.

Referência: Tipos no SQLite.

Chave primáriaPET Estatística UFSCar

O que é uma Primary Key?

Primary Key — PK

Identifica cada linha de forma única. Pode ser uma coluna ou uma combinação de colunas.

No nosso banco

clientes.id_cliente é INTEGER PRIMARY KEY.

Duas pessoas podem ter o mesmo nome; seus IDs precisam ser diferentes.

PK é uma regra de identificação, não um tipo de dado. Aqui o tipo é INTEGER e a regra é PRIMARY KEY.

Chave estrangeiraPET Estatística UFSCar

O que é uma Foreign Key?

Foreign Key — FK

Declara que um valor deve corresponder a uma chave da tabela referenciada.

No nosso banco

pedidos.id_cliente aponta para clientes.id_cliente.

Vários pedidos podem usar o mesmo cliente: a FK pode se repetir.

Ligaçãopedidos.id_cliente → clientes.id_cliente

O nome id_cliente sozinho não cria uma FK. Precisamos declarar FOREIGN KEY (...) REFERENCES .... Com NOT NULL, cada pedido precisa informar um cliente.

A chave referenciada pode ser PRIMARY KEY ou UNIQUE. Referência: FKs no SQLite.

Crie após pedidos e produtos. A tabela tem uma PK composta, duas FKs e quantidade com valor padrão 1.

▶ confere o exemplo e mostra uma saída prevista. Execute o Python no notebook para rodar no SQLite.

quantidade INTEGER NOT NULL DEFAULT 1: se quantidade for omitida no INSERT, o banco usa 1. NOT NULL exige um valor; DEFAULT define o valor usado na omissão.

DEFAULT 1 não exige quantidade positiva. Para essa regra, usamos CHECK (quantidade > 0).

Tipos de JOINPET Estatística UFSCar

INNER vs LEFT

INNER JOIN

Mostra apenas clientes que têm pedido.

LEFT JOIN

Mostra todos os clientes, inclusive sem pedido.

Essa diferença só fica clara porque a base tem clientes sem pedido de propósito.
